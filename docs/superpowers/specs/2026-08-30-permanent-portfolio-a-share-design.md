# A 股永久投资组合研究与模拟设计

## 1. 决策

在现有 Stock Analyze 系统中增加一个独立的 `permanent_portfolio_v1`
研究域，使用 20 万元初始资金分别运行两套组合：

1. 固定永久组合：股票、长期国债、现金、黄金各占 25%，采用
   `15%/35%` 阈值再平衡。
2. 动态永久组合：使用冻结的双动量排名，每月在四类资产之间分配
   `40%/30%/20%/10%`。

该研究不修改 `a_share` 或 `cn_qdii_etf` 的正式策略、账户、模型
Registry、竞赛配置或现有 Challenger。历史研究、盲测和前向纸面结果
必须分开存储和展示。

## 2. 研究问题

唯一研究问题是：

> 在中国境内可交易 ETF 上，固定四资产永久组合与低自由度趋势倾斜
> 永久组合，能否在成本后获得比单一股票资产更低的波动和回撤；动态
> 倾斜能否在不破坏四资产最低配置的前提下改善收益风险比？

开发期结果不得用于更换标的、窗口、权重档位、成本或调仓频率。
2025-2026 盲测结果不得用于修复开发期结论。

## 3. 资产映射

两套策略共享以下冻结标的：

| 类别 | 代码 | 名称 | 角色 |
| --- | --- | --- | --- |
| 股票 | `510300.SH` | 华泰柏瑞沪深300ETF | 中国大盘权益与经济增长 |
| 长期国债 | `511260.SH` | 国泰上证10年期国债ETF | 通缩与利率下行保护 |
| 现金 | `511880.SH` | 银华日利ETF | 流动性与短期现金收益 |
| 黄金 | `518880.SH` | 华安黄金ETF | 通胀、货币与极端风险保护 |

四只基金均在 2018 年前成立，能够覆盖完整开发窗口。冻结单一标的而
不是历史中动态选择 ETF，可避免规模、流动性和存续状态带来的事后
选择偏差。

外部基础资料参考：

- `510300.SH`: https://q.fund.sohu.com/q/gk.php?code=510300
- `511260.SH`: https://xueqiu.com/S/SH511260
- `511880.SH`: https://fundf10.eastmoney.com/jjgg_511880.html
- `518880.SH`: https://finance.sina.com.cn/fund/quotes/518880/bc.shtml

实现阶段必须使用 Tushare 基金主数据和交易所日历再次验证基金代码、
上市日期、交易状态和资产类别，并把原始响应摘要及校验和写入数据
清单。网页资料不能替代生产数据证据。

## 4. 数据合同

### 4.1 时间范围

- 指标预热：最晚从 `2016-12-01` 开始采集，确保 2018 年首个信号
  已有完整的 12 个月历史。
- 开发期：`2018-01-01` 至 `2024-12-31`。
- 盲测期：`2025-01-01` 至封存时四只标的共有的最近完整交易日。
- 前向纸面期：盲测一次性开启并完成后，从下一可执行交易日开始。

确定盲测结束日时只能检查交易日与字段完整性，不得读取收益、排名或
组合指标。结束日一经写入研究声明便不可缩短或延长；数据不完整时
研究失败关闭，不得静默改变窗口。

### 4.2 输入字段

每只 ETF 每个交易日至少需要：

- `ts_code`、`trade_date`
- `open`、`high`、`low`、`close`
- `vol`、`amount`
- 基金复权因子或可证明等价的累计净值调整字段
- 交易状态和上市状态

`ts_code` 和 `trade_date` 必须显式按字符串读取。收益、信号与净值
统一基于总收益复权价格；成交价使用未复权下一交易日开盘价。若复权
链、分红处理或单位无法验证，则全研究失败关闭。

### 4.3 完整性

以上海证券交易所交易日历为主日历。停牌时允许用最近有效收盘价进行
账面估值，但禁止成交。ETF 零成交日仅在下一笔实际行情的 `pre_close`
与缺口前一笔实际 `close` 一致时按不可交易日处理；尾部缺口、价格不
连续或其他无法解释的缺失价格、重复代码日期、非正价格、复权跳变或
校验和变化均阻止回测和盲测开启。

原始数据、规范化数据和研究声明分别生成 SHA-256 清单。Dashboard
只读取已完成且校验通过的版本化产物。

## 5. 组合规则

### 5.1 共用执行规则

- 每套策略初始现金为 `200000.00` 元，账本彼此独立。
- 只做多，不融资，不卖空，不使用杠杆。
- ETF 最小交易单位为 100 份。
- 佣金为单边成交额的 3 bps，最低 5 元。
- 滑点为单边 5 bps。
- ETF 印花税为 0。
- 信号在交易日收盘后产生，订单最早在下一交易日开盘执行。
- 卖出先于买入；买入按目标金额缺口从大到小执行。
- 整手约束后的未投资余额保留为账户现金。
- 无有效开盘价或处于停牌状态的订单保持待执行，不使用未来价格补单。

所有指标和比较都使用成本后账户净值。

### 5.2 固定永久组合

首个可执行日将四类资产目标权重设为各 25%。此后每个交易日收盘后
使用成本后账户净值计算实际权重：

- 若所有类别均在 `[15%, 35%]` 内，不生成订单。
- 若任一类别低于 15% 或高于 35%，四类资产目标全部恢复为 25%。
- 阈值判断使用未四舍五入的权重；恰好等于 15% 或 35% 不触发。
- 恢复订单在下一可执行开盘成交。

### 5.3 动态永久组合

每月最后一个共同交易日收盘后计算信号，下一可执行交易日开盘调仓。
对股票、长期国债和黄金计算：

```text
momentum_6_1  = adjusted_close[t-1 month] / adjusted_close[t-6 months] - 1
momentum_12_1 = adjusted_close[t-1 month] / adjusted_close[t-12 months] - 1
cash_6_1      = cash_adjusted_close[t-1 month] / cash_adjusted_close[t-6 months] - 1
cash_12_1     = cash_adjusted_close[t-1 month] / cash_adjusted_close[t-12 months] - 1
score         = 0.5 * (momentum_6_1 - cash_6_1)
              + 0.5 * (momentum_12_1 - cash_12_1)
```

现金类别的分数固定为 `0`。四类资产按分数降序映射到
`40%/30%/20%/10%`。分数相同时按固定类别顺序
`cash, bond, gold, equity` 排在前面，避免运行环境造成非确定结果。

动态策略不加入波动率缩放、止损、宏观状态、估值过滤、参数搜索或
临时 ETF 替换。任一所需观察值缺失时，当月不调仓并记录原因。

## 6. 回测与盲测协议

### 6.1 封存流程

研究状态机为：

```text
draft -> development_sealed -> development_complete
      -> holdout_opened -> holdout_complete -> forward_ready
```

进入 `development_sealed` 前必须写入：

- 配置文件内容与 SHA-256；
- 四只标的和资产类别；
- 规则版本与完整参数；
- 成本和整手规则；
- 开发期和盲测期；
- 输入数据清单；
- 当前 Git commit；
- 允许生成的指标和图表。

普通开发命令硬性拒绝读取 `2025-01-01` 及以后的输入。只有一次性的
盲测开启命令可读取封存窗口；若状态已经是 `holdout_opened` 或更晚，
再次开启必须失败。

### 6.2 基准

使用相同的 20 万元初始资金、执行日和成本假设计算三个冻结基准：

1. `510300.SH` 买入持有；
2. 四只 ETF 各 25% 买入后永不再平衡；
3. `511880.SH` 买入持有。

基准不得因结果改变。基金无法成交形成的余款保持现金。

### 6.3 指标

每个阶段独立计算，不跨窗口衔接净值：

- 累计收益和年化收益；
- 年化波动率；
- 相对现金 ETF 日收益的 Sharpe；
- 相对现金 ETF 的 Sortino；
- 最大回撤和回撤持续时间；
- Calmar；
- 正收益月份比例；
- 相对各基准的超额收益；
- 年化换手率、成交次数和总交易成本；
- 63 个交易日滚动收益与滚动波动；
- 年度收益和月度收益矩阵；
- 每日四类资产实际权重与目标权重。

同时生成 2 倍滑点和佣金的成本压力结果，但压力结果不改变主回测参数。

### 6.4 结论规则

开发和盲测结果可以是正面、负面或数据不足，均须原样保存。不得因
动态组合落后而修改窗口或权重，也不得因某一年度表现好而选择性报告。

`forward_ready` 只要求：

- 数据与复权合同通过；
- 无前视检查通过；
- 账本恒等式通过；
- 成交成本和整手规则通过；
- 所有声明产物校验和一致；
- 开发和盲测结果已经不可变落盘。

历史收益不是启动隔离纸面观察的门槛，也不构成正式策略晋级依据。

## 8. 组件边界

实现拆分为以下职责单一的单元：

1. **配置与声明**：解析冻结规则，生成和校验研究状态及哈希。
2. **ETF 数据物化**：采集并验证基金日线、复权、交易状态和交易日历。
3. **信号引擎**：纯函数计算阈值再平衡或双动量目标权重。
4. **组合回放**：复用现有成交和账本语义，处理下一开盘、成本、整手、
   停牌和现金。
5. **指标与报告**：按窗口独立计算指标、曲线、年度和月度结果。
6. **前向纸面运行器**：在盲测完成后每日幂等更新两个隔离账户。
7. **Dashboard 资源**：只读取已完成产物，返回有界 JSON。
8. **React 工作区**：展示阶段、策略对比、收益波动、权重和交易记录。

采集任务和回测命令可以访问数据提供者；Dashboard 请求处理器不得发起
任何提供者调用。

## 9. Dashboard 设计

左侧导航新增独立的“永久组合”研究工作区。页面不是正式策略页的第三种
策略，也不改变现有市场切换语义。

页面从上到下包含：

1. 阶段切换：开发期、盲测期、前向纸面期；
2. 关键指标条：两套策略与基准的收益、波动、最大回撤和收益风险比；
3. 归一化净值曲线；
4. 回撤曲线与 63 日滚动波动；
5. 四资产实际权重堆叠图和动态策略目标权重；
6. 年度收益与月度收益表；
7. 调仓记录、成本和未执行原因；
8. 研究声明、数据完整性、规则哈希和盲测状态。

盲测未开启时，页面只显示“已封存，未开启”和声明摘要，不返回任何
盲测收益字段。资源部分不可用时仅对应区域降级，其余已校验结果继续
显示。

## 10. 错误处理

以下情况必须失败关闭：

- 研究状态跳转非法或盲测重复开启；
- 配置、输入或结果哈希不一致；
- 使用了 2025 年以后数据生成开发期信号；
- 标的代码、日期或单位无法验证；
- 复权链不完整或分红未进入总收益；
- 下一开盘成交被同日收盘信号污染；
- 任一账户出现负现金、负持仓或资产恒等式不平；
- Dashboard 产物引用未完成运行。

失败记录包含阶段、日期、标的、错误代码和安全结果，不记录密钥或完整
提供者响应。

## 11. 测试与验收

### 11.1 单元测试

- `15%/35%` 边界、触发后四类恢复 25%；
- 双动量窗口、现金超额、排名、平分规则和固定权重映射；
- 月末信号与下一开盘执行；
- 佣金下限、滑点、整手和资金不足；
- 停牌、缺失价格、复权异常和重复日期；
- 收益、波动、Sharpe、Sortino、回撤、Calmar 和换手；
- 状态机、哈希校验和盲测重复开启拒绝。

### 11.2 性质与集成测试

- 任一目标权重均在 `[0.10, 0.40]` 且总和为 1；
- 固定组合不触发阈值时不交易；
- 任何交易后的现金与持仓数量均非负；
- 每日 `cash + market_value = total_value`；
- 开发运行无法读取 2025 年以后的分区；
- 相同输入和配置生成字节级一致结果；
- Dashboard API 不调用数据提供者；
- 缺失单个资源时页面局部降级。

### 11.3 完成验收

除仓库通用测试外，必须完成：

```bash
git diff --check
python3 -m compileall -q stock_analyze tests
python3 -m unittest discover -s tests
cd frontend/dashboard && npm test && npm run build
```

还需验证开发封存、一次性盲测开启、防重复开启、两个 20 万元独立账本、
Dashboard 桌面与移动视口、以及接口不泄露未开启盲测字段。

## 12. 非目标

- 不接入券商或真实下单；
- 不替换稳健防守或趋势进攻；
- 不训练模型；
- 不搜索最优 ETF、动量窗口、调仓频率或权重；
- 不使用 2025-2026 数据选择规则；
- 不把回测收益描述为未来收益承诺；
- 不因结果不理想删除、覆盖或重跑已封存证据。
