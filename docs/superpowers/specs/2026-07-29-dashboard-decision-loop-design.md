# Dashboard 决策闭环设计

## 目标

Dashboard 的首屏回答五个问题：

1. 系统正在交易哪些市场和策略？
2. 情报语料处理到了哪一步？
3. 情报因子是否已经进入模型？
4. 哪个模型版本正在研究、验证或正式使用？
5. 正式策略本期是否真的使用了模型，最终怎样影响订单和收益？

页面只展示真实链路状态。未形成 Champion、因子仍在观察、正式策略未应用预测时，连接显示为等待或未采用，不用视觉连线暗示已经生效。

## 信息架构

左侧导航调整为：

- `决策总览`：系统主线和当前影响状态，作为默认入口。
- `策略竞赛`：按市场对比稳健防守与趋势进攻。
- `单策略分析`：查看持仓、成交、预测应用证据和净值。
- `模型迭代`：查看每个市场的 Champion / Challenger 生命周期和独立模拟。
- `情报中心`：查看语料、抽取质量、结构化事件、因子验证和原文证据。

市场选择器只改变策略、模型和情报明细的观察范围；决策总览始终同时展示 A 股与境内上市跨境 ETF。页面不再把跨境 ETF 称为可直接交易的美股。

## 首屏结构

### 决策闭环

用五段状态轨道表达：

`公告与行情 -> 结构化情报 -> 研究因子 -> 模型版本 -> 正式策略`

每段显示当前数量、状态和一句结论。连接状态分为：

- `connected`：下游已有可核验采用证据。
- `research`：已产出但尚未达到采用门槛。
- `blocked`：缺少 Champion、有效因子或预测应用证据。

### 正式策略矩阵

按市场分两行，每行展示稳健防守、趋势进攻：

- 当前净值与累计收益。
- 每日任务状态。
- 模型策略：正式应用、规则降级或尚无决策证据。
- 实际应用候选数、模型版本、降级原因。

### 研究与生产分工

并列展示：

- 模型迭代：各市场当前候选、Champion、验证进度和本期模拟结果。
- 情报供给：最近抽取批次、确定事件数、可入模因子数、增量评估结论。

底部提供明确下钻按钮，分别进入模型迭代与情报中心。

## 数据契约

新增轻量接口 `/api/dashboard/system-overview.json`，只返回总览所需字段：

- 两个市场的模型迭代状态。
- 四条正式策略的最新模型应用证据。
- A 股公告情报链路、最新批次、因子供给和模型增量状态。
- 最近已确认事件的有限列表。

正式策略模型应用证据来自 `research_lineage.sqlite3` 的最新 `decision_runs`，不通过前端猜测。接口保持有界、可缓存，不加载 K 线、全部订单或完整语料。

## 交互与视觉

- 延续现有深色交易终端风格，使用青色作为主交互色、金色仅标识稳健策略。
- 首屏以横向状态轨道和分栏矩阵组织，不叠套卡片。
- 状态节点可点击下钻；键盘焦点、加载、错误和空状态完整。
- 桌面端保持高信息密度；窄屏改为纵向轨道，文字不截断。

## 验收

- 首次进入不需要选择市场即可看见两个市场、两套策略、模型和情报主线。
- 无 Champion 时明确显示“正式策略当前规则驱动”。
- 情报因子未入模时明确显示“研究中”，并展示原因。
- 正式模型应用状态由最新决策链路数据支持。
- 所有旧的 `view` 路由仍可访问，浏览器前进后退正常。
- React 测试、Python API 测试、生产构建和桌面/移动浏览器截图均通过。
