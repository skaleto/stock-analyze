# Dashboard 三视图工作台设计

## 目标

解决当前页面同时出现双策略竞技场、侧栏策略切换和单策略明细所造成的上下文混乱。用户在任意滚动位置都应明确知道：正在比较两个策略，还是正在查看某一个策略。

## 信息架构

页面只保留一个全局市场选择器，并在左侧栏用树状导航表达两个层级：

- 一级菜单：`策略对比` / `单策略分析`。
- 二级子菜单：`单策略分析`激活时展开，包含`稳健防守` / `趋势进攻`。

`策略对比`只展示赛季净值、基准、收益风险、因子差异、市场与板块暴露、持仓重合度等双策略内容。`单策略分析`只展示当前策略的账户总览、预测预警、净值基准、持仓、成交时间线、证券 K 线、运行历史和目标订单。

策略对比页中的策略标题可直接进入对应详情页。详情页通过左侧菜单返回对比页或切换到另一个策略，正文区域不再重复模式或策略切换控件。

## 状态与导航

- 用户 URL 使用 `market`、`view` 和公开策略键：对比页为 `?market=cn_qdii_etf&view=compare`，稳健防守详情为 `?market=cn_qdii_etf&view=detail&strategy=defensive`，趋势进攻详情为 `?market=cn_qdii_etf&view=detail&strategy=trend`。旧的 `agent=claude|codex` 链接仅用于兼容，打开后立即规范化为新地址；底层历史账户主键不暴露在用户 URL 中。
- 对比模式通过浏览器历史状态保留最后选择的策略，地址栏本身不携带策略参数；返回单策略分析时可恢复原对象。
- 浏览器刷新、前进和后退恢复同一视图。
- 切换市场时优先保留当前视图；若该市场没有对应策略，则回到对比页或该市场的首个策略。
- 对比页不请求单策略的六组资源接口；进入详情页后再按需加载。

## 视觉原则

- 保留现有深色专业终端风格，不更换主色盘。
- 稳健防守继续使用低饱和琥珀色，趋势进攻继续使用青色。
- 左栏一级菜单采用完整行按钮，当前页以青色边线和背景强调。
- `单策略分析`下的二级策略菜单缩进呈现，稳健防守使用低饱和琥珀色，趋势进攻使用青色；父菜单与当前子菜单同时保留选中反馈。
- 正文顶部不再出现工作台导航，对比和详情内容也不在同一页面纵向堆叠。
- 窄屏下左栏变为顶部区域，一级菜单保持两列，展开的策略子菜单在下一行保持两列，图表和表格沿用现有响应式行为。

## 验收标准

1. 默认打开页面只看到双策略对比内容，不出现目标订单、持仓组合或单策略净值图。
2. 点击任一策略后，分析模式切换为单策略分析，并显示该策略完整明细。
3. 左侧栏包含`策略对比`和`单策略分析`两个一级菜单；单策略模式下展开两个策略子菜单，正文区域没有重复导航。
4. 分析模式与策略对象通过父子菜单表达，URL 与两层状态双向同步，浏览器前进后退可用。
5. 对比页不发送单策略资源请求，详情页仍保持增量加载和旧响应隔离。
6. 桌面和移动端无重叠、溢出或无法识别的当前视图。
7. 新生成的 Dashboard 链接不出现 `agent=claude` 或 `agent=codex`；旧链接可用并自动迁移。
