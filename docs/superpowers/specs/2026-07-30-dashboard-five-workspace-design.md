# Dashboard 五工作区重构设计

## 1. 背景

现有 Dashboard 已经具备策略对比、单策略持仓、模型迭代、情报语义链和运行历史，但信息被分散在不同层级：

- 同一层导航混放“策略对比”和“单策略对象”，用户难以判断当前观察维度。
- 模型页面使用“当前迭代、质量矩阵、数据输入”等内部概念，无法直接回答训练进度、测试结果和正式采用状态。
- 情报页面偏重公告语义链，没有同时说明传统行情、财务、技术因子从哪里来以及被谁使用。
- 运行历史位于单策略页面底部，无法呈现每日主任务链、后台回填、周期计划和人工介入事项。
- `App.tsx` 同时承担路由、导航、页面组合和资源加载，继续直接叠加页面会扩大耦合与重复请求。

2026-07-29 的 `dashboard-decision-loop` 设计已经完成决策总览主线。本设计扩展到完整 Dashboard，并取代其导航与下钻部分；总览数据契约和“不虚构连接状态”的原则继续保留。

## 2. 目标

Dashboard 固定为五个可理解的工作区：

1. `决策总览`：系统从数据到策略的当前连接状态。
2. `策略工作台`：双策略对比与单策略交易明细。
3. `模型研究`：数据准备、训练、验收、模拟和正式采用进度。
4. `数据与情报`：结构化数据与文本情报如何形成因子并供给策略和模型。
5. `运行中心`：今日任务链、后台队列、周期计划、运行历史和人工介入事项。

用户进入任一页面后，都应能在十秒内回答：

- 我现在看的是哪个市场、哪个工作区和哪个对象？
- 当前结果是成功、运行、等待、研究中还是失败？
- 下游是否真的采用了上游产物？
- 需要我做什么，还是系统会自动继续？

## 3. 非目标

本次改造不包含：

- 修改选股、下单、模型训练、因子门槛或模拟交易逻辑。
- 重做现有线上持仓分组、证券行、净值图、K 线和交易明细组件。
- 将运行中心做成启动、停止、重跑 systemd 服务的远程控制台。
- 在浏览器中展示无界日志、完整语料、全部预测或全部历史订单。
- 把内部 `claude`、`codex`、`model_shadow` 名称重新暴露给用户。

## 4. 设计原则

### 4.1 真实状态优先

页面只展示后端可核验的数据。以下状态不能被画成已经连接：

- 情报因子仍在观察，不能显示为已参与训练。
- 没有 Champion，不能显示为正式策略已使用模型。
- 任务等待上游，不能显示为失败。
- 回填积压很大但 Worker 正常运行，不能显示为系统故障。

### 4.2 当前状态代替模块说明

主页面节点只展示名称、数量、时效和状态，不放大段“这个模块是做什么的”。

点击节点后展示当前系统中的实际内容：

- 数据源、覆盖率、最近更新时间和缺口。
- 模型版本、样本数、指标和未通过项。
- 任务开始结束时间、结果、下游和错误摘要。

### 4.3 视觉沿用线上基线

正式实现以 `frontend/dashboard/src/styles.css` 和现有 React 组件为唯一视觉基线：

- 保留当前深色交易终端风格。
- 复用青色主交互色、金色研究/等待状态、现有字体、边框和 6px 圆角。
- 复用线上表格、状态徽标、分段控件、抽屉和持仓组件。
- 模型、数据和运行预览稿只确定信息架构，不作为视觉像素标准。
- 不引入新的渐变、大圆角卡片、营销页式标题或另一套颜色系统。

## 5. 全局信息架构

### 5.1 左侧导航

左侧导航顺序固定：

```text
决策总览
策略工作台
  策略对比
  单策略分析
    稳健防守
    趋势进攻
模型研究
数据与情报
运行中心
```

`策略工作台` 是唯一有对象子层级的入口。其他四个工作区不再出现策略子菜单。

### 5.2 市场范围区域

左侧导航上方始终保留同一尺寸、同一位置的市场范围区域，避免按钮忽隐忽现：

- 策略工作台、模型研究、数据与情报：可切换 `A股` 和 `跨境ETF`。
- 决策总览：显示两个市场均被覆盖；点击市场可进入对应下钻页。
- 运行中心：默认 `全部市场`，可筛选 A 股、跨境 ETF 或仅异常。

控件语义可以随工作区变化，但容器位置、尺寸和视觉保持一致。

### 5.3 路由

用户可见 URL 不使用内部 Agent 名称：

```text
?view=system
?view=strategy&mode=compare&market=a_share
?view=strategy&mode=detail&strategy=defensive&market=a_share
?view=strategy&mode=detail&strategy=trend&market=cn_qdii_etf
?view=model-research&market=a_share
?view=data-intelligence&market=a_share
?view=operations&scope=all
```

兼容旧的 `view=compare`、`view=detail`、`view=model-iteration`、`view=model-shadow` 和 `view=intelligence`，首次解析后使用 `replaceState` 规范化为新路由。

旧 URL 中的 `agent=claude|codex|model_shadow` 仅用于一次性兼容解析，规范化后必须移除。

## 6. 五个工作区

### 6.1 决策总览

保留现有已认可的五段主链：

```text
公告与行情 -> 结构化情报 -> 研究因子 -> 模型版本 -> 正式策略
```

每段显示当前数量、状态和下钻入口。页面继续同时呈现：

- 两个市场和两套正式策略。
- 当前模型候选、Champion 和模拟状态。
- 情报抽取、标准事件、因子供给和模型采用状态。

总览是跨市场入口，不承载完整表格、历史日志或单股详情。

### 6.2 策略工作台

工作台内部使用二级模式：

- `策略对比`：收益、风险、持仓、交易和决策差异。
- `单策略分析`：稳健防守或趋势进攻的独立账户。

单策略页面继续使用现有线上组件和顺序：

1. 账户指标。
2. 当前持仓。
3. 净值与基准。
4. 模型应用证据、预测与风险。
5. ETF 研究或 A 股个股分析。
6. 交易时间线与策略摘要。
7. 目标订单。

不改变 `PortfolioSection` 的板块分组、证券行样式和明细抽屉。

策略页面必须明确显示：

- 当前是规则驱动、模型增强还是模型降级。
- 使用的正式模型版本；没有则显示“未采用”，不显示内部空值。
- 本期模型候选数、实际采用数和降级原因。

### 6.3 模型研究

模型研究使用五阶段进度链：

```text
数据准备 -> 模型训练 -> 测试验收 -> 模拟运行 -> 正式采用
```

#### 数据准备

展示：

- 已接入数据源和缺口。
- 候选特征、已选特征和点时数据状态。
- 结构化特征与情报特征分别有多少。

#### 模型训练

展示：

- 3、5、10、20 日模型版本。
- 训练样本数、训练日期和产物位置。
- 算法族、模型制品和预测产物是否完整。

页面称其为“研究模型”，不把四个预测周期误解成四套正式策略。

#### 测试验收

展示：

- Rank IC、ICIR、Brier、AUC、命中率提升、扣费超额收益、换手等指标。
- 每个版本通过和未通过的门槛。
- 当前 `0 / N` 通过时，直接列出阻塞项。

#### 模拟运行

展示：

- 当前候选版本及其独立模拟账户。
- 已完成观察周期和所需周期。
- 本期预测漏斗、入选证券、交易、挂单和保持现金原因。
- A 股与跨境 ETF 分别显示自己的候选版本。

#### 正式采用

展示：

- Champion 版本。
- 正式策略采用矩阵。
- 采用日期、回滚版本和模型覆盖率。

没有 Champion 时显示“正式策略仍由规则驱动”，不是空白页面。

### 6.4 数据与情报

页面以两条并行供给链展示：

```text
结构化数据：
行情与财务 -> 清洗与质量 -> 传统量化因子 -> 策略与模型供给

文本情报：
公告与政策 -> 下载与解析 -> 语义事件 -> 情报因子
```

两条链最终汇入“实际使用去向”矩阵：

| 使用对象 | 结构化数据 | 传统因子 | 情报因子 | 当前影响 |
| --- | --- | --- | --- | --- |
| 稳健防守 | 是否使用 | 是否使用 | 是否使用 | 选股/下单影响 |
| 趋势进攻 | 是否使用 | 是否使用 | 是否使用 | 选股/下单影响 |
| 研究模型 | 特征数量 | 特征数量 | 观察/采用 | 训练/预测影响 |
| 候选模拟账户 | 是否使用 | 是否使用 | 是否使用 | 模拟交易影响 |

每个节点可下钻：

- 行情与财务：数据域、来源、范围、最近交易日和使用位置。
- 清洗与质量：缺失、异常值、时间对齐、点时契约和降级处理。
- 传统量化因子：估值、质量、成长、趋势、风险等因子组。
- 公告与政策：来源、累计文档、当日新增、游标和新鲜度。
- 下载与解析：已下载、已解析、积压、可重试失败和终止失败。
- 语义事件：执行器、提示词/Schema 版本、成功、无事件、隔离和失败。
- 情报因子：覆盖率、激活率、Rank IC、消融结果和采用建议。

文本情报链可以显示历史回填仍在进行，但必须把“回填进度”和“每日增量是否新鲜”分开。

### 6.5 运行中心

运行中心是只读观测页面，分四层。

#### 今日主任务链

```text
情报增量
  -> 行情与研究快照
  -> 特征、预测与评估
  -> 双策略及候选模型模拟
  -> Dashboard 聚合与通知
```

节点状态统一为：

- `成功`
- `运行中`
- `等待计划时间`
- `等待上游`
- `失败`
- `已跳过`

点击节点显示结果、开始、结束或下次计划、耗时、下游任务和有限错误摘要。

#### 后台队列

独立显示：

- PDF 下载与解析回填。
- 情报对账。
- LLM 语义抽取。

后台积压不会自动把主链标记为失败。只有连续失败、租约卡死或新鲜度超限才升级为异常。

#### 周期计划

使用 `每日 / 每周 / 每月` 标签页展示已安装的真实 timer：

- 时间。
- 任务名称。
- 自动或需要人工。
- 上次结果和下次触发。

页面从实际 systemd timer 状态读取，不在前端硬编码计划。

#### 历史与人工介入

最近运行默认只展示关键任务，支持按主链、情报、失败和市场筛选。

“需要你介入”仅包括系统无法自动恢复的事项：

- 凭据失效。
- 连续失败达到阈值。
- 磁盘或队列超过安全阈值。
- 模型/因子质量门槛需要人工决策。

普通可重试失败、正常等待和历史回填积压不进入人工事项。

## 7. 前端架构

### 7.1 组件边界

将 `App.tsx` 中路由与页面组合职责拆分：

```text
App
  WorkspaceShell
    WorkspaceRail
    MarketScopeControl
    WorkspaceHeader
  DecisionOverviewPage
  StrategyWorkspacePage
  ModelResearchPage
  DataIntelligencePage
  OperationsPage
```

共享组件仅在确实复用时提取：

- `StageFlow`
- `MetricStrip`
- `StatusBadge`
- `DetailPanel`
- `BoundedTable`

现有 `PortfolioSection`、`PerformanceChart`、`InstrumentDrawer` 等保持原组件。

### 7.2 路由边界

把 URL 解析、旧路由兼容和规范化移动到独立 `workspaceRoute.ts`。页面组件只接收规范化后的：

```ts
type WorkspaceRoute = {
  view: WorkspaceView;
  market?: "a_share" | "cn_qdii_etf";
  mode?: "compare" | "detail";
  strategy?: "defensive" | "trend";
  scope?: "all" | "a_share" | "cn_qdii_etf" | "exceptions";
};
```

内部 Agent 映射只存在于路由适配层和 API 调用层。

### 7.3 数据加载

每个工作区只加载当前首屏需要的有界接口：

- 决策总览：`system-overview.json`
- 策略工作台：沿用拆分后的 overview/performance/portfolio/predictions 等资源
- 模型研究：新增 `model-research.json?market=...`
- 数据与情报：新增 `data-intelligence.json?market=...`
- 运行中心：新增 `operations-center.json?scope=...`

详细记录延迟加载：

- 单个模型版本。
- 单个数据源。
- 单个情报事件或文档。
- 单次运行详情。

切换工作区时取消旧请求。一个页面的部分接口失败，不阻塞其他页面。

## 8. 后端数据契约

### 8.1 模型研究接口

返回：

- 五阶段状态与数量。
- 数据源和特征摘要。
- 模型版本和训练产物摘要。
- 验收指标与未通过项。
- 候选模拟决策和版本生命周期。
- Champion 与正式策略采用矩阵。

不返回完整预测表、模型二进制或全部交易历史。

### 8.2 数据与情报接口

返回：

- 结构化数据源健康状态。
- 特征选择与传统因子分组。
- 文档目录、下载解析、抽取与事件统计。
- 情报因子验证摘要。
- 策略/模型实际使用矩阵。

“实际使用”必须来自策略配置、训练特征清单、决策 lineage 和模型 registry，不由前端根据因子是否存在进行猜测。

### 8.3 运行中心接口

返回：

- 当前时间和快照时间。
- 今日主任务链。
- 后台 Worker。
- 已安装 timer 的上次/下次触发。
- 最近有界运行记录。
- 人工介入事项。

systemd 读取使用固定 allowlist 和短 TTL 缓存，不在每个组件中分别执行命令。读取失败时返回：

```json
{
  "status": "unavailable",
  "last_known_at": "...",
  "reason": "runtime_status_unavailable"
}
```

页面继续展示 run ledger 的最后已知记录，不把整个接口变成 500。

## 9. 性能约束

- 非策略工作区不得触发 strategy overview/performance/portfolio/predictions 全套请求。
- 首屏接口响应体目标不超过 250 KB。
- ECS 热缓存接口目标响应时间小于 500 ms。
- 表格首屏最多返回 20 行，更多记录分页或按需加载。
- 运行中心不读取完整 journal；失败详情最多返回有界错误摘要。
- 前端保留上一次成功快照，刷新失败时显示“数据可能过期”和时间戳。

## 10. 错误与空状态

- `0 个可入模因子`：有效研究结论，不是加载失败。
- `0 个入选证券`：展示决策漏斗和保持现金原因。
- `等待上游`：展示上游名称和计划时间。
- 数据源缺失：展示具体来源和受影响特征。
- 部分接口失败：对应区块显示错误，其余区块继续可用。
- URL 参数无效：规范化到默认工作区并移除无效参数。

## 11. 测试与验收

### 11.1 前端

- 路由解析、旧 URL 兼容和 `agent` 参数清理测试。
- 五工作区导航与市场范围控件测试。
- 模型五阶段切换测试。
- 数据双供给链节点下钻与使用矩阵测试。
- 运行中心周期切换、任务下钻和状态语义测试。
- loading、partial error、stale、empty 和 unavailable 状态测试。

### 11.2 后端

- 三个新增摘要接口的 schema、边界和 payload 大小测试。
- 因子/模型“实际采用”证据来源测试。
- systemd allowlist、TTL 缓存和不可用降级测试。
- 运行等待、失败、跳过和成功状态映射测试。

### 11.3 浏览器验收

桌面与移动视口均验证：

- 左侧工作区和市场范围位置稳定。
- 文本、表格、节点和按钮不重叠。
- 进度链在窄屏可纵向阅读。
- A 股与跨境 ETF 切换更新数据但不改变工作区。
- 前进、后退和刷新保持当前工作区。
- 线上深色风格、持仓组件和图表风格没有退化。

## 12. 实施顺序

1. 提取路由与稳定导航，不改变现有页面内容。
2. 落地模型研究五阶段页面和专用接口。
3. 落地数据与情报双供给链和使用矩阵。
4. 落地运行中心只读接口与页面。
5. 完成旧路由兼容、性能测试和视觉回归。
6. 验证后删除被新页面完全取代的旧呈现逻辑，不删除底层数据与审计产物。

## 13. 发布与回滚

- 新旧路由在一个发布周期内同时可用。
- 新接口均为只读，不改变模拟交易、训练或定时任务。
- 前端静态构建与后端 API 可独立回滚。
- 若新页面异常，恢复旧页面入口，不回滚数据链和运行产物。
- 发布前必须通过 React 测试、Python API 测试、生产构建和桌面/移动截图验收。

## 14. 成功标准

- 用户不再需要理解 `claude`、`codex`、`model_shadow` 才能使用页面。
- 模型研究能明确回答“接了什么数据、训练了什么、指标如何、是否模拟、是否采用”。
- 数据与情报能明确回答“传统因子和情报因子分别来自哪里、被谁使用、是否影响决策”。
- 运行中心能明确回答“今天跑到哪、下次何时、失败在哪、是否需要人工”。
- 页面风格与现有线上 Dashboard 一致，策略工作台的持仓体验不退化。
