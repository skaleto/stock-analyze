# 项目维护与保留策略

更新日期：2026-08-18

## 当前真相入口

日常开发和运维只需要阅读以下文档：

- `system-overview.md`：系统边界、架构、数据与任务总览。
- `system-harness.md`：开发、部署、巡检和故障处理命令。
- `competition-runbook.md`：A 股与跨境 ETF 模拟策略运行规则。
- `announcement-intelligence-runbook.md`：公告采集、解析、语义抽取和因子供给。
- `announcement-intelligence-executor-contract.md`：可替换大模型执行器契约。
- `operator-alerting-setup.md`：飞书告警配置。
- `tushare-token-setup.md`：Tushare 凭据配置。

历史实施计划、阶段说明和旧设计稿不再作为运行依据，集中保存在
`archive/document-history/`。当前预注册研究合同和不可变结果仍保留在
`docs/superpowers/`。

## 数据保留

必须保留：

- 模拟账户状态、净值、订单、交易和运行账本。
- 当前行情、财务、资金流和回测缓存。
- 最新可复现实验所需的特征、标签、事件快照。
- 正式模型、配置、指标、决策、审计记录和版本血缘。
- 情报数据库、原始材料对象引用、结构化事件和质量报告。

可以清理：

- 虚拟环境、`node_modules`、Python 缓存和构建缓存。
- 临时诊断、截图、原型页面、失败任务工作目录。
- 已汇总试验的逐行预测文件；保留模型、指标、决策和交易摘要。
- 已被新版本替代且可重建的旧特征、标签和技术事件快照。

## 自动保留周期

- 临时文件：成功后立即删除；失败文件最多保留 7 天。
- 应用日志：保留 14 天并轮转压缩。
- 部署备份：保留最近 3 份和最近一次已验证回滚点。
- 研究试验：保留正式版本、当前候选和最近 5 次失败摘要。
- 大体积原始归档：上传 OSS、核对校验和后删除本机和 ECS 副本。

## 变更纪律

1. 新功能完成后，把长期有效内容合入上述当前文档。
2. 实施计划不长期留在 `docs/`；完成后由 Git 历史承担追溯。
3. 生成物必须位于已忽略目录，不能混入源码提交。
4. 删除模型或数据前，先证明没有运行时读取方，并保留可复现输入与摘要。
5. 每月运行一次结构审计，检查失效链接、孤立配置、重复脚本和磁盘增长。
